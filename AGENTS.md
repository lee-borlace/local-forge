# LocalForge maintainer instructions

Read README, docs/DESIGN.md, docs/INSTALLATION.md, docs/SECURITY.md and docs/ROADMAP.md. This is a configuration-first global OpenCode v2 distribution, not a new coding agent. Target repositories must work without preparation. Prefer native config/agents/skills and established upstream tools before custom code. Only add custom code for missing deterministic capabilities or enforcement that declarative mechanisms cannot implement. Do not add private API dependencies, mandatory repo scripts, external telemetry, cloud escalation, or general-purpose shell to strict profile. Preserve explicit user permissions and do not claim sandboxing.

Run `npm test`; tests are offline, use disposable roots and a mock API. Update file inventory and rationale for every install path/new module, plus test results and honest limitations. Before release validate actual OpenCode API and Windows using docs/SMOKE-TEST.md. Do not equate a mock with live integration. Keep existing user settings intact; back up and avoid overwriting modified managed files. Document every upstream version and optional feature. MIT-licensed source; do not vendor upstream code without reviewing its license. Keep content/ and manifest.json authoritative. Do not duplicate the package in global plugins/; use the public setup lifecycle and runtime registrations. Every physical payload must have a documented owner, purpose and cleanup behaviour.
